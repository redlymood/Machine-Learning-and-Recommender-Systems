# ТЗ: Random Lunch Menu Generator (веб-приложение)

## Роль
Ты — фронтенд-разработчик. Сгенерируй **готовый рабочий код** одностраничного
веб-приложения (не только README). Итог должен открываться двойным кликом по
файлу и работать без сборки.

## Что делает приложение
Простой «рекомендатель обеда»: пользователь жмёт кнопку — приложение случайно
выбирает одно блюдо из фиксированного списка и показывает его название вместе с
подходящей картинкой и лёгкой анимацией появления.

## Обязательные требования

### 1. Проверяемость картинок
- У каждого пункта меню обязана быть картинка, которая **реально существует** и
  корректно отображается.
- **Не выдумывай имена иконок/классов.** Если используешь иконочную библиотеку —
  сверяй каждое имя с официальным списком; не уверен, что имя валидно, — не
  используй его.

### 2. Согласованность текста и картинки
- Картинка обязана соответствовать блюду по смыслу (нельзя ставить ложку вместо
  тако, тарелку вместо пасты и т.п.).
- Если для блюда нет подходящей картинки — либо убери это блюдо, либо смени
  источник картинок на тот, где подходящий символ гарантированно есть.

### 3. Без критичной зависимости от внешней CDN
- Приложение должно корректно отображаться **офлайн и без сторонних CDN**.
- Предпочитай ассеты без внешних зависимостей: **эмодзи** (рендерит системный
  шрифт) или файлы, лежащие в самом репозитории.
- Если внешняя библиотека всё же нужна — предусмотри запасной вариант на случай,
  что она не загрузилась.
- **Для этого приложения используй эмодзи.**

### 4. Тайминг и асинхронность
- Разрешается короткий эффект «Thinking…» (~500 мс) перед показом результата.
- Эффект должен быть **безопасным при быстрых повторных кликах**:
  - при новом клике отменяй ранее запланированный показ (`clearTimeout`);
  - блокируй кнопку (`disabled`) на время задержки и снимай блокировку по
    завершении;
  - для честного перезапуска CSS-анимации появления делай принудительный reflow
    между снятием и добавлением класса анимации.
- Никаких гонок, мерцания и «пролистывания» промежуточных блюд.

### 5. Структура данных
- Список блюд — массив объектов, где **название и картинка (эмодзи) заданы в
  одном объекте одной операцией** (например `{ name: "Pizza", emoji: "🍕" }`).
- Меню — 12 блюд.

### 6. Оформление
- Один файл `index.html` со встроенными стилями и скриптом.
- Адаптивная вёрстка (десктоп/телефон).
- Случайный выбор запускается и при загрузке страницы.

## Критерии приёмки (проверь перед выдачей и перечисли результат)
1. Каждый из 12 пунктов меню показывает **корректный, соответствующий эмодзи**.
2. **3 быстрых клика за 1 секунду** не ломают экран: нет мерцания, нет
   пролистывания лишних блюд, итог соответствует последнему клику.
3. Страница **работает без сети** (нет внешних `<link>`/`<script>` на CDN).
4. Перечисли сделанные допущения.
